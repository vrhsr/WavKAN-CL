**Methodology:** Six parallel full-file-read audits (data/leakage, model/architecture, training/seeds, evaluation/statistics, ablations+governance-scripts, figures/tables), each instructed to read every assigned file completely and cite exact file:line. Severity definitions: **CRITICAL** = directly undermines a headline claim or shows a mechanism that can misrepresent results (whether or not currently exploited in the live manuscript). **HIGH** = a real correctness/fairness/traceability defect in something that currently feeds, or could easily feed, a reported number. **MEDIUM** = dead code, duplication, or fragility that is a standing risk but not currently miscalculating anything confirmed. **LOW** = cosmetic, uncertain, or low-impact.

Status values used below: `OPEN` (found, not yet actioned), `NEEDS-DECISION` (requires your sign-off on whether it's a bug fix or a methodological change per rule 7).

## Zero-automated-coverage note (cross-cutting)

The repository's single most safety-critical guarantee — the inter-patient DS1/DS2 split with no patient overlap between train and test — has **zero automated regression coverage** anywhere in the repo. `split.py`'s own disjointness assertions only run if the file is executed directly as `__main__`; neither `smoke_test.py` nor `test_ablation.py` (the only two test-like files in the repo) touches the data, training, or evaluation clusters at all. This is the direct target of the domain-specific integrity rule agreed for this audit ("no metric/model/seed selection may ever touch test-set labels") — the split mechanism itself is correctly implemented everywhere it was checked (see Positive Findings below), but it currently has no regression test, so a future refactor could break it silently. **Recommend a regression test for Phase 4 regardless of whether any other finding here requires one.**

**FIXED 2026-08-12** — see CHANGELOG.md. `tests/test_split_integrity.py` now covers: `split.py`'s own three-way disjointness and DS1 partition, the 201/202 same-patient split, and (per H16) that the *alternate* `VAL_RECORDS` lists in `process_data.py`/`process_extended_rr.py`/`process_sequence.py` never overlap `TEST_RECORDS` either — while explicitly documenting (not silently "fixing") that those alternate lists still diverge from `split.py`'s own list, since reconciling them is the open H16 methodological question, not a bug this test should paper over.

## Positive findings (recorded for balance and completeness, per audit rules distinguishing bugs from what's actually sound)

- Within-run checkpoint/early-stopping selection is validation-based, not test-based, across all 10 training scripts audited in the training-loop cluster — the test-set-contamination pattern (C5's sibling issue, the original `find_best_seed.py`/`check_seed_42.py` finding) is confined to *cross-run* seed/model selection, not epoch-level checkpointing within a run.
- Zero-shot INCART/SVDB/PTB-XL evaluation code is genuinely zero-shot — no `.fit`/`.train()`/`.backward()` calls anywhere in `eval_multidataset.py` or `eval_ptbxl.py` (full-file read confirmed); the live manuscript's PTB-XL number (0.233 Macro-F1) matches the honest script's real output exactly (independently confirmed by the orchestrator, see C8).
- `src/benchmark_latency.py`'s warm-up handling is correct: a discarded warm-up loop runs before the timed loop begins.
- `src/process_ptbxl.py`'s train/test split is a genuine patient-ID-level split (hard numeric threshold on an actual patient-identity column) — correct in mechanism, independent of the label-granularity concern (H12).
- No augmentation-before-split and no joint train+test normalization-statistic computation was found anywhere in the 12-file data/preprocessing cluster — the core train/test independence property holds at the array level everywhere it was checked.
- `src/metrics_full.py:167-204`'s `statistical_comparison` correctly guards against tiny-N Wilcoxon (falls back to `nan` below n=6) — a safeguard absent from the other call sites flagged in H8.
